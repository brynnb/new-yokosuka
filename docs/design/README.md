# Design and adaptations

These documents discuss intentional New Yokosuka adaptations and proposed
integration work. Their recommendations are not implementation status.
Where they describe an existing boundary, follow the linked implementation
guide and focused tests for the current contract.

- [Shenmue I narrative adaptation](shenmue1-narrative-adaptation.md): shared-world
  policy, personal story context, and intentional departures from the original.
- [Storyline gameplay integration](storyline-gameplay.md): current ownership,
  retained research and verification for personal story events.
- [Story event template](story-event-template.md): a reusable authored event
  specification, connected progression checklist and authored opening
  investigation, with explicit approximations.
- [Story move learning](story-move-learning.md): optional teachers, scroll pickups
  and purchases, saved ownership, and fidelity boundaries.
- [Shenmue II Story feasibility](shenmue2-story-feasibility.md): available
  original inputs, verified format boundaries and a bounded first-slice plan;
  this is not implemented S2 Story coverage.
- [Nozomi's rescue](story-nozomi-rescue.md): implemented late-night rest/call,
  original presentation sources, clock boundaries and remaining challenges.

Keep temporary priorities, task checklists, and progress reports in ignored
`internal-docs/`. Durable design decisions should explain the tradeoff and link
to the implementation once adopted.
